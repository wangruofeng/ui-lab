# UI Lab 案例收录

先看项目的 `AGENTS.md`、`README.md` 和 `site/app/library.js`，确认现有来源、案例类型、路由和全站 UI 规则。用户只要求调研时，给出候选、可展示的行为和原始出处。用户要求收录时，再落地案例并验证。

## 判断收录范围

- 从原项目的官方目录、文档、源码或发布包核对案例名称、可操作行为和原始链接。区分有具体演示的条目、同一组件的参数变体，以及安装、概览等说明页。
- 选能让读者观察到具体设计行为的条目，例如拖动后的状态变化、按缩放级别显示的信息，或动画方向、相位、节奏。优先补充现有案例库缺少的交互。只有一条值得展示时，也可以独立收录。
- 逐项衡量交互价值和演示成本。多个条目如果只有颜色、尺寸等参数不同，把参数放进同一演示。机制不同且有可观察差异的条目可以分别收录。用户要求完整收录时，以核实过的官方清单逐项对账，说明合并或跳过的理由。
- 控件应帮助读者触发、观察或理解行为。先确认演示能让读者亲手完成关键操作，再决定是否收录。以 loading.dev 为例，旋转、错峰和扩散有不同可观察行为，尺寸、速度、暂停和重播可以共用控件。

## 选择演示类型

| 类型 | 适用条件 | 呈现方式 |
| --- | --- | --- |
| 前后对照 | 有明确的设计变化，两侧能用同一任务或条件比较结果 | 沿用现有对照模板，尽量只改变要讲解的变量 |
| 交互演示 | 单个效果本身值得操作或观察，例如一段动效、一个组件或一个画布行为 | 用单栏演示呈现。独立实现可按场景提供暂停、重播或重置 |

同一个来源可以混合使用两种类型。只有一个单栏案例时，沿用首页直接进入案例的规则；多个案例用来源详情页和分组目录。分组应体现机制或读者任务。

## 使用官方组件和示例

- 有官方组件和对应的官网示例时，直接使用官方组件和该示例的源码。逐个确认示例链接与具体变体，例如 shadcn/ui 的 Combobox 多选示例和 Date Picker 日期范围示例。
- 保留官网示例的数据、默认状态、控件、触发方式、操作顺序和反馈。收录说明可放在演示外层。对示例操作的增删和流程调整以用户的明确要求为准。
- 将组件、示例及其运行所需的依赖、样式、字体和素材打包到本地，纳入站点构建。独立嵌入时，按原示例所需配置外层环境，例如启用表单提交、剪贴板和下载，或挂载消息提示组件。
- 逐个打开对应的官网示例，对照本地构建产物的初始状态，执行同一组操作并核对反馈。官网预览不可操作时，继续对照官方源码和文档，在本地实测，并在交付时说明哪些步骤只能在本地验证。

## 落地和核验

1. 使用上游代码或资产时核对许可、保留必要声明并记录版本。采用独立实现时说明来源，验证关键行为与参考一致。静态标记和样式足够时，可在生成阶段转换，保持站点运行时轻量。
2. 按现有数据结构设置稳定的来源与案例 ID、简体中文标题或说明、原始出处和可验收的 `criterion`。复用模板和 `libraryHref()`。站点外层及独立实现复用项目控件与样式，包括原生单选下拉的 `.select-control`。将新增运行文件放入 `site/` 下对应的目录。
3. 运行 `npm run build`，检查首页入口、来源目录、案例直达链接、全站搜索和最终产物。实际操作每个新增演示的核心控件，覆盖窄屏、键盘焦点和适用的减少动态效果策略。批量收录时核对案例数据、演示实现和上游清单的 ID。确认至少一个现有前后对照案例仍可使用。
4. 交付时列出收录数量、分组、可操作内容、实现与上游的关系，以及实际验证范围。列出有意义的合并或遗漏。
